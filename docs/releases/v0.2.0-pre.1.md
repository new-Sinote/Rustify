## What this is

The first shipping build of Rustify: a native Windows host for the official Spotify Web Player, built on `wry` + `tao` + WebView2 instead of the Phase 3 Tauri spike.

The shell supplies the Windows integration and the memory lifecycle. Spotify's own player keeps ownership of sign-in, playback, DRM, the queue, and advertising.

## What changed from v0.1.0-pre.1

- Replaced the Tauri shell with a smaller `wry` + `tao` host.
- Added the `Normal -> Low` memory lifecycle: hydration trim, pause trim, periodic trim, and a post-gap trim at track and ad boundaries.
- Added a Spotify-style 40 px caption bar with custom minimize, maximize/restore, and close-to-tray buttons. Native resize borders and the DWM shadow/rounded corners remain.
- Hid the `Explore Premium` button and `Install App` link in the nav bar with a scoped stylesheet. Nothing else on the page is changed.
- Added window-state persistence, single-instance activation, tray show/hide/quit, navigation allowlist, popup/download blocking, and denied permissions.
- Removed all CDP and test-only launch flags from the shipping binary. They are compiled only with the `bench` Cargo feature.

## Certification

The release gate is the 35-minute periodic-trim soak plus a 10-minute hidden/paused run. Full method and per-sample data: [docs/CERTIFICATION_0.2.0.md](../CERTIFICATION_0.2.0.md).

| Gate | Target | Result |
|---|---|---|
| Playing PSS, every 5-minute soak sample | <= 400 MB | **PASS**, max 263.3 MB |
| Paused PSS, hidden 10-minute run | <= 300 MB | **PASS**, max 95.1 MB (mean 60.0) |
| Paused CPU | <= 1% of one core | **PASS**, 0.32% mean; 0.24-0.39% sustained |
| Idle CPU | <= 0.5% of one core | **PASS**, 0.24-0.39% sustained |
| Window ready | <= 500 ms | **PASS**, 272 ms warm; 271 ms fresh profile |

A launch-time hydration transient is excluded from the playing soak, as in the Phase 4 method: the page hydrates for about a minute, and the hydration trim reclaims memory asynchronously. The soak starts once that hydrated state exists.

## Advertising and scope

Ads are served by Spotify and play normally. Rustify does not block, skip, mute, filter, proxy, or re-stream them. It does not circumvent DRM, extract audio, extract credentials or tokens, or use undocumented Spotify APIs.

The only page modification is the stylesheet that hides two nav-bar upsell elements. It is a cosmetic rule, not an ad-blocking or request-filtering feature. Playback, DRM, ads, and network traffic are untouched.

## Install

1. Download `Rustify-0.2.0-x64-setup.exe`.
2. Run it. The installer is per-user and does not require an administrator prompt.
3. Windows SmartScreen will warn because the binary is unsigned. Choose **More info -> Run anyway**.
4. Launch **Rustify** and sign in at `open.spotify.com`.

**Requirements:** Windows 10/11 x64, the Evergreen WebView2 Runtime, and a Spotify account. Free accounts work.

**Uninstall:** Settings -> Apps -> Rustify. The uninstaller asks whether to remove the local profile and settings. In a silent uninstall the data is kept.

## Files and data

- Install directory: `%LOCALAPPDATA%\Programs\Rustify`.
- App data: `%LOCALAPPDATA%\Rustify`.
- WebView2 profile: `%LOCALAPPDATA%\Rustify\WebView2` (contains your Spotify session, like a browser profile).
- Diagnostic log: `%LOCALAPPDATA%\Rustify\rustify.log` (rotated at 2 MB; no track titles are logged).

Rustify has no telemetry. Spotify receives the same web-player traffic it would receive in a browser.

## Known limitations

- Windows 10/11 x64 only.
- No auto-update and no code signing yet.
- Social-login popups are blocked by the strict top-level allowlist. Email/password sign-in works.
- The first launch on a machine that has never initialized the WebView2 runtime can be slower; one earlier run measured 652 ms. Normal starts and starts with a fresh app profile measured 271-288 ms. See [the certification report](../CERTIFICATION_0.2.0.md#5-startup-and-hydration).
- The custom chrome is a second WebView. It is small after a trim but does add a renderer to the process tree.
