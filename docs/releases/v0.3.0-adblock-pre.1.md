# Rustify v0.3.0-adblock-pre.1 - Experimental ad-mute build

> **Experimental and uncertified.** This build changes how Spotify ads behave: it detects an audio ad and mutes the player, and it can skip tracks in the opt-in discovery test mode. It has **not** been tested against a real Spotify Free account. Zero real advertisements have been observed. Do not treat it as an ad blocker or as a certified release.

**Released:** 2026-11-26  
**Status:** Experimental pre-release. Not the default download. Not certified.  
**Asset:** `rustify-adblock.exe` (portable x64 executable; no installer)  
**Tag:** `v0.3.0-adblock-pre.1`  
**Licence:** MIT for Rustify. No third-party filtering payload is bundled.

## What this is

This is the first public build of the native ad-mute proof of concept. It hosts the official Spotify Web Player exactly as the stable build does, then watches the WebView2 document title for Spotify's advertisement marker. When the marker appears, Rustify mutes the player WebView; when the title changes back, it unmutes. DRM, authentication, audio delivery, and the page itself are not modified.

It also includes **Automatic Ad Discovery**, an opt-in test mode that skips confirmed normal tracks until an ad appears. Discovery exists to make ad-mute testing practical on a free account. It is off by default and must be started from the `AD` panel.

## What it does

- Detects the web player's advertisement title through the documented WebView2 `DocumentTitleChanged` event.
- Mutes the player WebView with `ICoreWebView2_8::SetIsMuted` and unmutes when the ad title ends.
- Rechecks the title at 120 seconds of continuous mute, extends every 30 seconds while the ad is still detected, and fails open at 15 minutes. It never leaves the app permanently muted by design.
- Adds an opt-in **Automatic Ad Discovery** panel (`AD` button) with interval, maximum skips, live state, ON/OFF badge, and skip/ad/mute-cycle counters.
- Skips only confirmed track titles, through the documented Windows media-session API (`TrySkipNextAsync`). It stops skipping immediately on an ad, an unknown title, or a pause, and fails closed on a rejected skip, a disabled Next, an ambiguous session, or a title mismatch.
- Enables Chromium's `MediaSessionService` flag so WebView2 publishes a media session to Windows. This is scoped to this build and disclosed.

## What it does not do

- **It does not block ad delivery.** The ad is still streamed and may still be billed. Rustify only silences the player while the ad title is present.
- **It does not bundle uBOL or any network filter.** No request is blocked or modified. The `adblock ublock` variant is not part of this release.
- **It does not guarantee ad detection.** Only the English marker `Advertisement` as the whole title or the final separator segment is recognized. Localized or reversed titles are treated as unknown, so the ad may play audibly.
- **It does not bypass Spotify's skip limit.** Discovery uses normal Next and stops when Spotify rejects or disables it.
- **It does not touch DRM, Widevine, credentials, tokens, or the audio stream.**
- **It does not include an installer, auto-update, or code signing.**

## Install and first run

1. Download `rustify-adblock.exe`.
2. Put it in a folder and run it. There is no installer and no administrator prompt.
3. Windows SmartScreen will warn because the binary is unsigned. Choose **More info -> Run anyway**.
4. Sign in at `open.spotify.com` with a temporary account. Do not use your main account for ad experiments.
5. Play a track, click `AD` in the title bar, set the interval and maximum skips, then click **Start**. Discovery skips normal tracks until an ad appears; it stops skipping when the ad is detected.
6. Click **Stop** at any time. Stopping discovery does not unmute an ad that is already muted.

To keep the stable profile untouched, override `LOCALAPPDATA` for the process:

```powershell
$env:LOCALAPPDATA = Join-Path $env:TEMP 'rustify-adblock-test'
.\rustify-adblock.exe
```

**Requirements:** Windows 10/11 x64, the Evergreen WebView2 Runtime, and a Spotify account.

**Uninstall:** close the app and delete `rustify-adblock.exe`. To remove local data as well, delete `%LOCALAPPDATA%\Rustify`. No registry entries or services are created.

## Files and data

- App data and WebView2 profile: `%LOCALAPPDATA%\Rustify` (shared with the stable build unless `LOCALAPPDATA` is overridden).
- WebView2 profile: `%LOCALAPPDATA%\Rustify\WebView2`.
- Diagnostic log: `%LOCALAPPDATA%\Rustify\rustify.log`.
- The log records state transitions, counters, failure reasons, and (debug builds only) a boolean title-match result and the media-session AUMID. It does not write track titles, media titles, cookies, or tokens.

## Risk and scope

- **Account risk.** This build changes ad behaviour. Spotify's terms restrict circumventing restrictions, and ad avoidance may put an account at risk. Use a temporary account.
- **False mute.** A real track whose title ends in `- Advertisement` could be muted. The watchdog bounds the mute at 15 minutes, but that is still a long silent interval.
- **Missed ads.** The parser is English-only. A localized or differently formatted ad title is unknown and is not muted.
- **Strict session rule.** Discovery fails closed if any other Windows media session exists, even a paused one. Close other players before using it.
- **Skip consumption.** Discovery uses real Next actions and consumes Spotify skips. It stops when Spotify refuses, but it can still alter your listening state.
- **Media keys.** `MediaSessionService` changes how WebView2 publishes its session to Windows. Media-key and background-playback behaviour must be rechecked on a real account.
- **No certification.** The 0.2.0 memory, CPU, startup, installer, and ad-row gates do not apply to this build. A new certification is required before it can be called stable.
- **Unsigned and manual.** There is no auto-update and no signature.
